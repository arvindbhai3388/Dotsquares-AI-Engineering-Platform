# Code of Conduct

This is an internal Dotsquares engineering platform repository (see [`LICENSE`](LICENSE)),
used across Dotsquares .NET delivery teams and client engagements. This page sets the baseline
for professional conduct in issues, pull requests, and any other discussion on this repo.

## Expected conduct

- **Be direct and specific, not personal.** Critique the change, the proposal, or the reasoning
  — e.g. "this skips server-side authorization" rather than characterizing the person who wrote
  it.
- **Assume good faith.** Most disagreements here are about tradeoffs (which stack, which
  pattern, how strict a standard should be), not about competence.
- **Follow this platform's own discipline** when proposing or reviewing a change: see
  [`CONTRIBUTING.md`](CONTRIBUTING.md) and
  [`wiki/AI-Workflow-Discipline.md`](wiki/AI-Workflow-Discipline.md)'s
  Analyze → Propose → Approve → Implement → Test → Review sequence. Disagreeing with a standard
  is legitimate; forking or silently working around it instead of raising the disagreement is
  not (see the ["What if I disagree with a standard in this wiki?"](docs/FAQ.md) FAQ entry).
- **Respect scope.** This repo is used by every client engagement built on it — a change here
  is not the same as a change in one client repo. Keep proposals and reviews focused on the
  actual problem, not an opportunity to relitigate unrelated conventions.
- **Handle security concerns responsibly.** Follow [`SECURITY.md`](SECURITY.md) rather than
  posting a suspected secret leak or exploitable issue in a public issue/PR thread.
- **No harassment, discriminatory language, or personal attacks** — the same standard that
  applies in any other Dotsquares internal work channel applies here.

## Scope

This applies to all interactions on this repository: issues, pull requests, code review
comments, and any linked discussion.

## Escalation

If you experience or witness conduct that falls short of this standard, contact the framework's
maintainers — the same escalation path used elsewhere in this repo for platform-level concerns
(see [`CONTRIBUTING.md`](CONTRIBUTING.md) and [`docs/FAQ.md`](docs/FAQ.md)). This is an internal
process for an internal repository — there is no separate public-facing enforcement channel.
