# Migrate RxJS-Based Component State to Signals

**Category:** Angular
**Use when:** A component manages its own local state through `BehaviorSubject`s/manual subscriptions purely for template display, and signals would remove boilerplate without losing needed reactive behavior.

## Prompt

Before converting anything, read the component and classify each piece of RxJS-based state into one of three buckets, and report the classification before proceeding: (a) state that's purely local, synchronously derived, and only ever consumed by this component's own template — a strong signals candidate; (b) state that's fed by a genuinely asynchronous external stream (an `HttpClient` call, a WebSocket, a `Router` event, another service's `Observable`) — still convertible, but via `toSignal()` at the boundary rather than by rewriting the source as a signal; (c) state that depends on RxJS-specific operators for its correctness (`debounceTime`, `switchMap` cancellation semantics, `combineLatest` timing, `retry`) — flag these as **not** simplified by a straight signal conversion, since signals have no built-in equivalent for time-based or cancellation-sensitive operators, and propose keeping the RxJS pipeline for just that slice, converting only its final output to a signal via `toSignal()` for template consumption.

For bucket (a), replace `private readonly foo$ = new BehaviorSubject<T>(initial)` plus its `.next(...)` calls with `foo = signal<T>(initial)` and `.set()`/`.update()`; replace any `combineLatest([...]).pipe(map(...))` used purely to derive local UI state with `computed(() => ...)` reading the relevant signals directly. Remove the corresponding `.subscribe()` in the template/class and reference the signal directly in the template (`{{ foo() }}`) — the `async` pipe is no longer needed for a plain signal, and don't leave a leftover `foo$ | async` alongside a new signal for the same value.

For bucket (b), keep the source `Observable` but convert it to a signal at the point the component consumes it: `data = toSignal(this.service.getData(), { initialValue: ... })` (require an `initialValue` if the template needs a non-undefined value before the first emission resolves). Note explicitly that `toSignal()` must be called in an injection context (field initializer, constructor, or with an explicit `injector` option) — flag any place this would require restructuring where the call currently sits.

Remove now-unused `Subscription`/`takeUntil`/`takeUntilDestroyed` cleanup for anything fully replaced by signals — a plain `signal()` has no subscription to leak — but do not remove cleanup for streams still kept as RxJS per bucket (c). Update tests: replace assertions that drove state via `.next(...)` and read it via `.subscribe()`/`fixture.detectChanges()` timing with direct `.set()` calls and reading the signal's current value; for `toSignal()`-backed state, flush the underlying `Observable` (via `HttpTestingController` or a test scheduler) and then assert the signal reflects the emitted value after `fixture.detectChanges()`. Confirm every existing test for this component still passes after the conversion, not just newly added ones.
